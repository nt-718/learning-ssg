# 第18章 ハイブリッド型の素晴らしい世界

## 18.1 なぜハイブリッドが普通なのか

一つの組織は複数の仕事、環境、時間軸、専門性を抱える。純粋形は比較のための道具であり、現実の有効な組織は複数の力を動的に均衡させる。2023年版の書評でも、大学の専門職コア、プログラム型の管理部門、プロジェクト型の研究チームが共存する例が示されている。[Stanford Social Innovation Review](https://ssir.org/books/reviews/entry/organizations_again)

## 18.2 ハイブリッドの基本形

### ブレンド型

同じ単位の中で複数の論理が密接に混ざる。

例：交響楽団は、指揮者の統合、演奏家の熟達、演奏中の協働、楽譜による標準化を同時に使う。

### 寄せ集め型

組織内の別々の単位が異なる形態を持つ。

例：製薬会社の研究はプロジェクト型、臨床専門家はプロフェッショナル型、製造はプログラム型、製品事業は事業部型。

### 時間的ハイブリッド

局面によって形態を切り替える。

例：通常は分権的な専門組織でも、重大事故時は一時的にパーソナル型の指揮へ移る。危機後は権限を戻さなければ恒常的集権化になる。

### 境界横断型

組織外のパートナーと異なる論理を接続する。

例：プラットフォーム企業が、内部のプログラム型基盤と、外部開発者のプロジェクト型活動をルールとAPIで結ぶ。

## 18.3 自然なハイブリッドと不自然なハイブリッド

自然なハイブリッドでは、異なる要素が異なる問題を処理し、接続方法が明確である。不自然なハイブリッドでは、相反する要求を同じ人へ同時に課す。

| 自然な組合せ | 不自然な組合せ |
|---|---|
| 安全手順は標準化し、例外判断は専門家へ | 専門家に裁量責任を負わせつつ全判断を承認制にする |
| 探索チームと運用チームで指標を分ける | 新規事業を既存事業と同じ月次利益で評価する |
| 事業部へ市場責任を与え、共通基盤は全社化する | P/L責任を与えながら価格・採用・商品を本社が決める |
| 全社原則を共有し、地域ごとに実装を変える | 全社統一と現地最適の両方を説明なく要求する |

## 18.4 裂け目を管理する

ハイブリッドでは、異なる成功基準が衝突する。

- 営業の速度対法務の慎重さ
- 研究の学習対製造の再現性
- 専門家の質対経営の費用管理
- 事業部の自律対全社プラットフォーム

解決は「仲良くする」ことではない。共通成果、最終決定権、相互サービス水準、例外手続、資源配分原則を決める。対立の構造を消せないなら、正当に処理する構造を作る。

## 18.5 ハイブリッド設計キャンバス

| 項目 | 記入内容 |
|---|---|
| 組織の錨 | 中心的能力・支配的な力 |
| 補完する力 | 錨だけでは処理できない課題 |
| 単位 | どこにどの形態を置くか |
| 境界 | 異なる形態が接する場所 |
| 接続装置 | 会議、役割、API、SLA、共通指標 |
| 決定権 | 境界問題を最終的に決める人 |
| 早期警戒 | 汚染・内耗を示す指標 |
