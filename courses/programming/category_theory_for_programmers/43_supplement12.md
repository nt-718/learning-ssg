# 結論

## 概要

この本を読む目的は、31個の圏論用語を覚えることではない。

圏論を学び終えたときに身につけたいのは、

> **「この複雑な問題の内部を直接解析する代わりに、構成要素、射、合成、保存される構造、普遍性として捉え直せないか」**

と考える習慣である。

圏論がプログラマーに与える最大の価値は、特定のライブラリでも、Haskellの特定の型クラスでもない。

それは、

> **複雑なシステムを、合成可能な構造として考えるための言語**

である。

この視点が、

- 型
- 関数
- API
- エラー処理
- 状態
- 再帰
- データ構造
- 抽象インターフェース

を一つの体系の中で捉えることを可能にする。

そして本書で何度も現れる、

\[
\text{圏}
\rightarrow
\text{関手}
\rightarrow
\text{自然変換}
\rightarrow
\text{米田}
\rightarrow
\text{随伴}
\rightarrow
\text{モナド}
\]

という道筋を、自分の言葉とコードで説明できるようになれば、

『プログラマーのための圏論』の主要部分は十分に理解できたと判断してよい。
