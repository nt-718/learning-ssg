# 第10章 自然変換

ここが第一の大きな難所。

## 1. これまで何を変換したか

関手は、

> 圏から圏への構造保存写像

だった。

では、

> 関手から関手への射

を考えられないか。

それが自然変換。

## 2. 定義

二つの関手、

\[
F,G:\mathcal C\to\mathcal D
\]

について、

自然変換

\[
\alpha:F\Rightarrow G
\]

とは、

各対象 \(A\) に対して、

\[
\alpha_A:F(A)\to G(A)
\]

を対応させるもの。

## 3. ただし「自然」でなければならない

任意の、

\[
f:A\to B
\]

について、

\[
G(f)\circ\alpha_A
=
\alpha_B\circ F(f)
\]

## 4. 自然性の四角形

```text
F(A) -----F(f)----> F(B)
 |                   |
αA                  αB
 |                   |
 v                   v
G(A) -----G(f)----> G(B)
```

どちらの経路でも同じ結果になる。

## 5. Haskell

典型的には、

```haskell
forall a. F a -> G a
```

のような多相関数が自然変換になる。

## 例

```haskell
safeHead :: [a] -> Maybe a
```

```haskell
safeHead []    = Nothing
safeHead (x:_) = Just x
```

## 6. なぜ `a` を調べないことが重要か

`safeHead` は、

```text
a = Int
```

か、

```text
a = String
```

かを知らない。

したがって型の具体的中身によって処理を変えられない。

これがparametricityを通して自然性と関係する。

## 7. よくある誤解

### 誤解

「自然」とは、人間の感覚で自然な変換。

### 修正

違う。

自然性とは、

> **関手の射に対する作用と整合している**

という数学的条件。

## 第1部総合整理

ここまでで、

```text
型          = 対象
関数        = 射
関数合成    = 射の合成
Maybe/List  = 関手
safeHead    = 自然変換
```

という階層を作った。

さらに、

```text
対象
 ↓ 射
対象

圏
 ↓ 関手
圏

関手
 ↓ 自然変換
関手
```

という一段ずつ抽象度が上がる構造が見える。
