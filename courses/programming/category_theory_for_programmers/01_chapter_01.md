# 第1章 圏：合成の本質

## 1. この章を学ぶ理由

圏論全体の出発点は、

> **「何を持っているか」ではなく「どう合成できるか」**

である。

プログラムも巨大な処理を直接書くより、

```text
A → B → C → D
```

という小さな処理の合成として構築する。

圏は、この「合成」という概念だけを抜き出した数学的構造である。

## 2. 正式定義

圏 \(\mathcal C\) は、

- 対象 \(A,B,C,\dots\)
- 対象間の射
- 射の合成
- 各対象の恒等射

からなる。

射

\[
f:A\to B
\]

と

\[
g:B\to C
\]

があれば、

\[
g\circ f:A\to C
\]

が存在する。

## 結合律

\[
h\circ(g\circ f)
=
(h\circ g)\circ f
\]

## 恒等射

各対象 \(A\) に、

\[
id_A:A\to A
\]

が存在する。

そして、

\[
f\circ id_A=f
\]

\[
id_B\circ f=f
\]

## 3. プログラミングで考える

```haskell
parse :: String -> Int
validate :: Int -> Bool
```

なら、

```haskell
validate . parse
```

は、

```haskell
String -> Bool
```

になる。

つまり型が、

```text
String → Int → Bool
```

と接続可能だから合成できる。

## 4. 圏論的な重要ポイント

圏論は対象内部の構造について何も要求しない。

対象が、

- 型
- 集合
- ベクトル空間
- データベース
- 状態
- 論理命題

のどれであってもよい。

必要なのは、

> 射があり、合成できること。

## 5. よくある誤解

### 誤解

「射＝関数」

### 修正

関数は射の重要な例だが、すべてではない。

圏によって射は、

- 関数
- 順序関係
- 線形写像
- 論理的含意
- プログラム

などになる。

## 6. 演習

### 問1

次の関数を合成せよ。

```haskell
f :: String -> Int
g :: Int -> Double
h :: Double -> Bool
```

### 解答

```haskell
h . g . f :: String -> Bool
```

### 問2

なぜ

```haskell
f :: A -> B
g :: C -> D
```

は一般に合成できないか。

### 解答

f の出力型 B と g の入力型 C が一致していないから。

## 7. 1分復習

圏とは、

> **対象と、合成可能な射からなる世界**

である。

そして圏論の第一テーマは、

> **合成**

である。
