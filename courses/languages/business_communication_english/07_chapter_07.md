# 第7章 進捗報告

良い進捗報告は、

Status  
Completed  
Remaining  
Risk  
Next Step

で構成します。

## 例

> The project is currently on schedule.

> We completed the UI implementation yesterday, and backend development is about 80% complete.

> The remaining work is mainly integration testing.

> The main risk is a potential delay in the external API review.

> We expect to complete testing by Friday.

## 7.1 RAG

プロジェクト管理では、

Red  
Amber  
Green

で状況を表すことがあります。

> The project is currently Amber because the vendor integration is running three days behind schedule.

## 7.2 問題報告

悪い：

> API is broken.

良い：

> We identified an issue with the payment API. Around 8% of requests are currently failing.

## 7.3 Impactを書く

問題そのものだけではなく影響を説明します。

> This may delay the release by one or two days.

> Customers can still use the existing payment method.

## 7.4 Ownerを書く

> The backend team is investigating the issue.

## 7.5 ETA

> We expect to have a fix by 4 p.m.

## 演習

1. 「プロジェクトは予定通りです。」
2. 「開発は80%完了しています。」
3. 「最大のリスクはAPI連携です。」
4. 「1〜2日遅れる可能性があります。」
5. 「現在原因を調査しています。」
6. 「午後3時に次の報告をします。」
7. 「顧客への影響はありません。」
8. 「一部ユーザーに影響しています。」
9. 「暫定対応を実施しました。」
10. 「恒久対応を検討しています。」

## ケーススタディ3　システム障害

## Initial Update

> We are currently investigating an issue affecting login for some users.

> The issue began at approximately 10:15 a.m.

> Our engineering team is working to identify the root cause.

> We will provide another update within 30 minutes.

## Second Update

> We have identified the cause of the login issue.

> The problem was related to a database connection limit introduced during this morning's deployment.

> We have applied a temporary fix, and login success rates have returned to normal.

> We are continuing to monitor the system.

## Final Update

> The incident has been fully resolved.

> We have also rolled back the configuration change that caused the issue and added an additional deployment check to prevent recurrence.
